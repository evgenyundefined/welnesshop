# CLAUDE.md

Витрина на Laravel 13 + Vue 3. Соглашения проекта:

- Сценарий = один инвокабельный класс в `app/Actions/<Домен>/`. Контроллер только
  переводит HTTP в вызов действия и обратно, бизнес-логики в нём нет.
- Зависимости инжектятся через конструктор или параметры метода. Глобальные
  хелперы (`request()`, `app()`, `auth()`) в приложении не используются.
- Параметры маршрутов резолвятся через route model binding, а не `findOrFail`
  внутри контроллера.
- Настройки модели задаются атрибутами Laravel 13 (`#[Fillable]`, `#[Hidden]`,
  `#[RouteKey]`, `#[Scope]`), а не protected-свойствами.
- Перечисления — нативные backed enum'ы (`enum Foo: string`).
- Деньги хранятся в минорных единицах целым числом плюс код валюты.
- В миграциях `created_at`/`updated_at` объявляются с
  `useCurrent()` / `useCurrentOnUpdate()`, чтобы значения проставлялись и на
  уровне БД.
- Комментарии пишутся только там, где код не может объяснить решение сам.
- Цвета берутся из двух семейств, объявленных в `@theme` (`resources/css/app.css`):
  `ink-*` — хром и текст, `gold-*` — акцент. Палитр Tailwind по умолчанию
  (`neutral-*`, `emerald-*` и прочих) в шаблонах нет, поэтому ребрендинг —
  правка одного блока.
- Guard'ы адресуются по имени через `App\Enums\Guard`, а не через guard по
  умолчанию: `auth`-middleware переписывает его на всё оставшееся время запроса.

## Контент страниц

Видимость страницы задаётся `App\Enums\PageVisibility`: `published` (в меню и по
ссылке), `unlisted` (только по прямой ссылке) и `draft` (404). Меню и футер
берут страницы через scope `listedInMenus()`, публичный endpoint пускает всё,
кроме черновика. Это не защита доступа: `unlisted`-страница открыта любому, кто
знает адрес.

Тексты страниц и промо-блока — HTML, введённый администратором. Он **хранится и
отдаётся как есть, без очистки**, и выводится через `v-html`. Это осознанное
решение владельца проекта, а не недосмотр: администратору доверена произвольная
разметка. Не добавляйте санитайзер и не сужайте `valid_elements` в редакторе,
не спросив.

Редактор — TinyMCE 6 (`resources/js/admin/components/RichEditor.vue`), собран
через Vite ESM-импорты, с `valid_elements: '*[*]'` и `verify_html: false`, чтобы
диалог «Исходный HTML» сохранял разметку дословно. Интерфейс переведён словарём
`resources/js/admin/tinymceRussian.js` — языковых пакетов в npm-пакете нет.

Оформление текста задаётся один раз в `.prose-page` (`resources/css/app.css`) и
дублируется для тела редактора в `resources/css/editor-content.css`. Правки
нужны в обоих файлах, иначе админка перестанет показывать то, что получится на
витрине. У правых колонок футера своя типографика `.prose-footer` — они лежат на
тёмном фоне, поэтому палитра `.prose-page` там не годится.

Любой блок, который выводится через `v-html`, вешает на себя
`useInternalLinkNavigation` (`resources/js/internalLinks.js`): в тексте лежат
обычные `<a href="/pages/…">`, и без перехвата клик перезагружал бы SPA целиком.

Картинки редактора живут в `content/` и подчищаются `PurgeOrphanedContentImages`
по факту замены текста. Полный обход папки делает только `content:prune` — он
видит и свежие загрузки, ещё не попавшие ни в один сохранённый текст, поэтому
удаляет лишь по `--force`.

## nginx и сертификаты

Прод-образ nginx не содержит `conf.d/default.conf`: его пишет
`docker/nginx/entrypoint.prod.sh` из шаблонов в `docker/nginx/templates`, выбирая
http- или https-вариант по наличию сертификата на томе. Тот же скрипт раз в
минуту перечитывает состояние и перезагружает nginx, поэтому первый выпуск и
каждое продление подхватываются без рестарта.

Общие location-блоки лежат в `docker/nginx/snippets/app.conf` и подключаются и
прод-шаблонами, и dev-конфигом — правка нужна в одном месте.

## Доставка

Стоимость доставки СДЭК всегда пересчитывается на сервере в момент оформления
(`App\Actions\Delivery\PriceDelivery`). Данные из браузера — только выбор:
город, пункт, код тарифа. Цену клиент не передаёт и передавать не должен.

Обращения к перевозчику живут в `app/Delivery/Cdek`. Тесты подменяют их через
`Http::fake()` — сеть в тестах не трогается никогда.

## Оплата

Уведомление ЮKassa не является источником правды: контроллер вебхука берёт из
него только id платежа и перечитывает платёж у ЮKassa авторизованным запросом.
Никогда не доверяйте статусу из тела уведомления — оно не подписано.

## Остатки

Точное число остатка не покидает сервер на витрине: `ProductResource` отдаёт
`stock_level` / `stock_label`, а не `stock`. Не возвращайте `stock` в этот
ресурс — на это есть тест
(`StockLevelTest::test_the_catalog_never_hands_out_the_exact_count`).

По той же причине поле количества на витрине ограничено
`shop.max_item_quantity`, а не остатком: `:max="остаток"` выдал бы точное число
обратно. Проверка «не больше остатка» живёт на сервере, в действиях корзины.

Админка использует `App\Http\Resources\Admin\ProductResource` и показывает
настоящее число — это намеренно.

## SEO

`<head>` витрины собирается на сервере (`ResolvePageMeta` + `storefront.blade.php`)
— краулер не исполняет скрипты и без этого не увидел бы ничего, кроме пустого
`<div id="app">`. Любой новый публичный маршрут витрины нужно добавлять в
`ResolvePageMeta`, иначе он молча уедет в `noindex`.

`public/robots.txt` намеренно не существует: файл на диске перехватил бы
маршрут `RobotsController`, а строку `Sitemap:` нужно отдавать с абсолютным
адресом, зависящим от домена. Не создавайте этот файл.

Скрытые страницы (`unlisted`) и черновики товаров отдают `noindex` и не входят
в `sitemap.xml` — это и есть смысл «скрытости», не «чините» это.

`documentTitle.js` берёт значения по умолчанию из `<meta name="site-title">` и
`<meta name="site-brand">`. Не зашивайте название магазина в JS: оно
редактируется в админке.

## Тесты

Каждое изменение покрывается на двух уровнях:

1. **Unit** — действие вызывается напрямую, проверяется состояние БД.
2. **E2E** — реальный HTTP-запрос через endpoint, с настоящим middleware и сессией.

Проверки флага в БД недостаточно: middleware может его не читать. Поведение
подтверждается через endpoint.

Когда тестируется запрет — проверяются все пути обхода, а не только прямой:
чужой заказ и чужая строка корзины, оформление после падения остатка, все
защищённые маршруты после выхода, а для блокировки — вход, живая сессия,
cookie «запомнить меня», корзина, оформление и оплата уже созданного заказа.

```bash
php artisan test --compact
php artisan test --compact --filter=ИмяТеста
vendor/bin/pint
npm run build
```

Docker для тестов не нужен: `php artisan test` работает прямо в проекте, база
для тестов — SQLite в памяти.

Проверка в браузере (Playwright + предустановленный Chromium) выявила несколько
вещей, которые PHPUnit пропустил: одну сессию на два guard'а, порядок утилит
Tailwind, не импортированную переменную в SFC. Для изменений, которые видит
пользователь, стоит поднять `php artisan serve` и посмотреть глазами.
